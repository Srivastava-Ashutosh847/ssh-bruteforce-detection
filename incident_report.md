# SOC Incident Investigation Report

## 1. Incident Summary

- **Incident Name:** Possible SSH Brute-Force Activity
- **Alert Source:** Python SSH Brute-Force Detection Tool
- **Severity:** Medium
- **Status:** Investigated — Simulated Lab Activity
- **Environment:** Kali Linux Virtual Machine

## 2. Alert Details

| Field | Value |
|---|---|
| Detection Type | Repeated SSH authentication failures |
| Source IP | 127.0.0.1 |
| Failed Attempts | 3 |
| Detection Window | 5 minutes |
| Alert Status | Investigation Required |

## 3. Detection Method

The Python detector retrieves recent SSH service logs using `journalctl`. It extracts source IP addresses from failed password events and counts attempts within the configured five-minute window. An alert is generated when the count reaches three or more failed attempts from the same IP.

## 4. Investigation Steps

1. Reviewed the alert generated by the detection tool.
2. Identified the source IP address as `127.0.0.1`.
3. Checked recent SSH authentication logs for failed login events.
4. Confirmed that the activity was generated during a controlled local lab test.
5. Reviewed the JSON alert saved in `alerts.jsonl`.

## 5. Findings

Three failed SSH login attempts were detected from the loopback address `127.0.0.1` within the configured monitoring window.

The loopback address refers to the local machine. The observed events were generated during testing and do not establish that an external attacker was involved.

## 6. Response and Disposition

- **Disposition:** Benign simulated activity.
- **Action Taken:** Validated the alert against local SSH logs.
- **Containment:** Not required for this controlled test.
- **Escalation:** Not required for the simulated event.

In a real environment, the analyst should verify the source host and account, review surrounding authentication activity, and follow the organization's escalation procedure before closing an incident.

## 7. Recommendations

- Monitor repeated authentication failures.
- Investigate unexpected source IPs and targeted accounts.
- Correlate authentication events with other security logs.
- Improve alert deduplication and incident tracking.
- Consider integrating the detector with a SIEM such as Wazuh.

## 8. Conclusion

This lab exercise demonstrated SSH log analysis, threshold-based detection, structured alert generation, and basic incident documentation. It represents a simulated investigation and is not evidence of a real-world attack.
